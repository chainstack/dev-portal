title: "Chainstack updates: October 11, 2026"
description: "The Chainstack MCP server adds five tools that manage node access rules, so your AI agent can restrict a Global Node to allowed IP addresses or origins."
---

**MCP Server**. The [Chainstack MCP server](https://mcp.chainstack.com) can now manage [access rules](/docs/access-rules), so your AI agent can restrict who calls a node's endpoints by client IP address or by the browser's `Origin` header. Five new tools list, create, update, and delete rules, and activate or deactivate every rule on a node at once. Access rules work on [Global Nodes](/docs/global-elastic-node) on paid plans, and a new rule does nothing until you activate it. When IP address rules and allowed origin rules are both active, a request must come from an allowed IP address and also send an allowed `Origin` header. Version 1.6 of the [Chainstack skill](https://mcp.chainstack.com/skill) adds an access rules workflow in which the agent confirms with you that the rules cover every IP address that calls the node before it activates them.

Validation errors from the Chainstack API now name the rejected field and the reason, and the server instructions and every tool description now fit within the 2,048-character limit of Claude Code, so Claude Code shows them in full. Connect at `https://mcp.chainstack.com/mcp`, or see the [discovery page](https://mcp.chainstack.com) for per-client setup.

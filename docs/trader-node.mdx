<Note>
  ### Trader Node deprecation: December 1, 2026

  Chainstack plans to deprecate Trader Nodes on December 1, 2026. We recommend moving your workloads to [Global Nodes](/docs/global-elastic-node) before then.

  Global Nodes cover what Trader Nodes were built for, and add more. They match Trader Node latency, add built-in failover for higher reliability, route each request from the nearest location, and provision instantly, so an endpoint is ready in under a second.

  To switch, deploy a Global Node from your [Chainstack account](https://console.chainstack.com/), then point your application to the Global Node endpoint in place of your Trader Node endpoint. Your latency stays the same. If you need help, [contact support](https://chainstack.com/contact/).
</Note>

<Check>
  ### Warp transactions

  Moving to a Global Node keeps [Warp transactions](/docs/warp-transactions). They are available on both Trader and Global Nodes, on Solana, Ethereum, and BNB Smart Chain.
</Check>

<Note>
Trader Nodes are available starting from the [paid plans](https://chainstack.com/pricing/).
</Note>

## Modes

For Trader Nodes deployed on most public chains, Chainstack supports the following modes:

* Full — a node that stores full blockchain data. However, it limits how many blocks are available for querying.
* Archive — a node that stores full blockchain data and an archive of historical states, which makes it possible to query any block since the chain genesis.

The mode also sets the billing class for every request on the node. A full-mode Trader Node bills every request at 1 RU. An archive-mode Trader Node bills every request at 2 RUs, regardless of the method or the block requested, including each WebSocket subscription notification. See [How your node type affects this](/docs/request-units#how-your-node-type-affects-this).

## Mode and mempool availability by region

Trader Nodes are bound to a single region, and the modes on offer differ from region to region. Check [Available clouds, regions, & locations](/docs/nodes-clouds-regions-and-locations) for the modes in your region.

Subscribing to pending transactions on a Trader Node works in every region and mode, and Trader Nodes do not serve `txpool_content`, `txpool_contentFrom`, or `txpool_inspect` in any region or mode. If you need the pool contents, deploy a [Dedicated Node](/docs/dedicated-node) and ask for the `txpool_*` namespace. See [What gives you mempool access](/docs/mempool-configuration#what-gives-you-mempool-access).

## Warp transactions

[Warp transactions](/docs/warp-transactions) propagate and land your transactions at the fastest speed possible. They are now a node [add-on](/docs/add-ons) you install on Trader and Global Nodes from the node's **Add-ons** tab, rather than a deployment-time option.

## Dedicated gateways

A dedicated gateway is one of the Trader Node customization features that is available on the [Enterprise plan](https://chainstack.com/pricing/).

Dedicated gateways process connections and traffic exclusively for a specific customer, avoiding potential issues from handling multiple customers' workload. This ensures a stable and reliable connection while reducing the likelihood of connection errors.



​Trader Nodes are deprecated and will be shut down on December 1, 2026. To ensure uninterrupted service, you must migrate your Trader Nodes to Global Nodes.
​This guide covers the differences between Trader Nodes and Global Nodes, how to identify your existing Trader Nodes, and step-by-step instructions for a smooth migration.
​What a Global Node Differs
​While Trader Nodes and Global Nodes serve similar purposes, Global Nodes introduce several architectural improvements and changes:
​Per-network host: Global Nodes use a streamlined, network-specific hosting format.
​New auth token: You will use a new authentication token associated with your Global Node deployment.
​Routing & Modes: Enhanced routing capabilities and flexible operating modes.
​Request Units: Standardized measurement for your API requests.
​Add-ons: Access to advanced features like Warp transactions.
​Access Rules: Fine-grained security configurations for your endpoints.
​How to Find Your Trader Nodes
​Before migrating, you need to locate your active Trader Nodes. You can identify them using the following indicators:
​Host pattern: Look for hosts containing nd-…p2pify.com.
​Platform API v1: Check for type shared combined with provider chainstack_managed or vzo.
​MCP node_tier: Use the Model Context Protocol (MCP) server tool to inspect nodes labeled under the Trader tier.
​Node usage traffic: Review traffic patterns under your dashboard's Node usage section.
​Note: Provider alone is not enough to identify a Trader Node, as Dedicated Nodes run on the exact same providers, and Platform API v2 does not return the node type.
​Reusing vs. Deploying a Global Node
​One Global Node per network: You only need a single Global Node to handle your requests for a specific blockchain network.
​Reuse or Deploy: Check if you already have an active Global Node on the target network. If you do, you can reuse it. If not, you will need to deploy a new one.
​Plan Node Limits and Migration Strategy
​Your subscription plan's node limit counts Trader Nodes as part of your total capacity.
​Migration Strategy: To avoid hitting your plan limit during migration, migrate one network at a time. By migrating sequentially, keeping one free slot available is sufficient to provision the new Global Node before deleting the old Trader Node.
​Endpoint URLs per Protocol
​Global Node URL structures vary slightly by protocol. Pay special attention to where the authentication token is placed:
​Avalanche: The auth token goes after the chain path (e.g., /ext/bc/C/rpc/<token>). Note that the old Trader Node format (/<token>/ext/bc/C/rpc) will return a 404 error on Global Nodes.
​Aptos: The auth token goes before /v1.
​Beacon Chain API: Uses the structure /beacon/<token>.
​Basic Auth: Supported for HTTPS (returns 200) and WSS handshakes (returns 101).
​Add-ons and Special Configurations
​Warp Transactions: Available on Global Nodes for Ethereum, BNB Smart Chain, and Solana Mainnet (paid plans required, along with extra usage requirements).
​MEV Protection: Note that Warp transactions are mutually exclusive with MEV protection and optimized submission. You must turn MEV protection off first on Ethereum and BNB Smart Chain before enabling Warp.

​If you are using the Chainstack MCP server to automate your infrastructure, follow the runbook format (similar to migrate-to-chainstack-with-ai).
​The tools used in the runbook include:
​list_nodes (with node_tier)
​get_deployment_options

​get_node
​delete_node

## View node access and credentials

To view the access information:
1. Click your project.
2. Click your network.
3. Click the node name.

This will give you the access and credentials to your nodes.

The examples below are for an Ethereum Mainnet Global Node. Dedicated Node endpoints use a per-node host, such as `nd-123-456-789.p2pify.com`, in the same formats.

Examples of your HTTPS node connection endpoints:

<CodeGroup>
  ```sh Key-protected
  https://ethereum-mainnet.core.chainstack.com/3c6e0b8a9c15224a8228b9a98ca1531d
  ```

  ```sh Password-protected
  https://user-name:pass-word-pass-word-pass-word@ethereum-mainnet.core.chainstack.com
  ```
</CodeGroup>

Examples of your WSS node connection endpoints:

<CodeGroup>
  ```sh Key-protected
  wss://ethereum-mainnet.core.chainstack.com/3c6e0b8a9c15224a8228b9a98ca1531d
  ```

  ```sh Password-protected
  wss://user-name:pass-word-pass-word-pass-word@ethereum-mainnet.core.chainstack.com
  ```
</CodeGroup>

Examples of your gRPC node connection endpoints (available for select protocols like Sui and Solana):

<CodeGroup>
  ```sh gRPC endpoint
  sui-mainnet.core.chainstack.com:443
  ```

  ```sh x-token
  b2a7442099925280a3184aef2cedd3a1
  ```
</CodeGroup>

<Info>
  gRPC endpoints use x-token authentication passed in the request metadata, rather than URL-based auth tokens. See [authentication methods](/docs/authentication-methods-for-different-scenarios) for details.
</Info>

To call several nodes with one auth token instead of each node's own auth token, attach the nodes to a multichain endpoint. See [Use Multichain API](/docs/multichain-api).

## Rotate a node auth token

You can replace a node's auth token on Chainstack without downtime. You generate a new auth token, move your applications to it while both tokens work, and then deactivate the old auth token. Rotate the auth token after a suspected leak, when someone with access to it leaves your team, or on a schedule.

A rotation replaces every credential that belongs to the auth token:

- The auth token in the HTTPS and WSS endpoint URLs
- The username and password for password-protected access
- The x-token for gRPC endpoints

To rotate an auth token, you need the **Admin** or **Editor** role in the organization that owns the node. See [Manage your organization](/docs/manage-your-organization) for roles.

<Steps>
  <Step title="Generate a new auth token">
    Open the node, click **Rotate token** next to **Access and credentials**, and then click **Generate new token**.

    **Access and credentials** now lists two auth tokens, each with its own endpoints and credentials:

    - **New token** — marked **Active**
    - **Old token** — marked **Active until rotation is completed**
  </Step>
  <Step title="Update your applications">
    In your applications, replace the old endpoint URLs, username and password, and x-token with the values listed under **New token**. Both auth tokens keep working until you complete the rotation, with no time limit.
  </Step>
  <Step title="Complete the rotation">
    Click **Complete rotation**, select **I have updated my applications to use the new endpoint URLs**, and then click **Deactivate old token**.
  </Step>
</Steps>

<Warning>
  Completing a rotation is permanent. Chainstack rejects requests that use the old auth token from the moment you click **Deactivate old token**.
</Warning>

How a rotation runs:

- Each auth token has at most one rotation in progress. You can click **Rotate token** again after you complete the current rotation.
- You end a rotation only by deactivating the old auth token. The new auth token stays active.
- If your node has more than one active auth token, the **API token** selector lists them. Select an auth token to rotate it, and rotate each auth token separately.
- A rotation doesn't change a [multichain auth token](/docs/multichain-api).

## View node requests metrics

You can view the data on requests made to your public chain project node.

To view the requests data:
1. Click your project.
2. Click your network.
3. Click the node name.
This will show you the data on the requests made to your node:

* Requests made — a chart of the total requests over HTTP and WebSocket for the selected period.
* Method calls — a breakdown of the method calls to the node over the selected period. Only available for HTTP requests.
* Response codes — a breakdown of the HTTP response status codes over the selected period. Only available for HTTP requests.

The data granularity is 1 minute.

The available timeframes are—1 hour, 6 hours, 12 hours, 24 hours, 7 days.

You can also see your total organization's [statistics](/docs/see-statistics).

## Switch the period

To switch the period of the displayed requests data:
1. Navigate to the **Metrics** section.
2. On your right, select the period.

## Download the aggregate data

To download the aggregate requests data:
1. In the **Requests made** section, click the hamburger button.
2. Click the format to download the aggregate data.

## Check Dedicated Node performance

A Dedicated Node shows its current CPU, RAM, storage, and latest block number as tiles in the **Node performance** section of the node's **Overview** tab.

To view the node performance:
1. Click your project.
2. Click your network.
3. Click the node name.

For what each tile shows, availability, and how to scrape the same metrics into your own monitoring stack, see [Dedicated Node monitoring](/docs/dedicated-node-monitoring#node-performance-on-chainstack).

## Delete a node

<Warning>
  To be able to delete a project or a network, you must first delete all nodes associated with the network.
</Warning>

To delete a node:
1. Click your project.
2. Click a network in the project.
3. Select a peer node to delete. Click **Edit** > **Delete**.

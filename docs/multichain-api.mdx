title: "Use Multichain API"

Multichain API gives you one auth token for several nodes. You create a multichain endpoint on Chainstack, attach the Global Nodes and Dedicated Nodes you want, and put the multichain auth token in the URL of each node instead of managing one auth token per node.

<Info>
  Multichain API is available on every plan, including the Developer plan.
</Info>

## What is a multichain endpoint?

A multichain endpoint is a named group of your existing nodes with one shared multichain auth token. The multichain auth token authorizes requests to each node in the group, so you keep a single secret in your environment variables or CI instead of one per node. Your nodes keep their own endpoint URLs and [auth tokens](/docs/authentication-methods-for-different-scenarios), and those auth tokens keep working.

A multichain endpoint can hold the following:

* One [Global Node](/docs/global-elastic-node) per protocol and network
* Any number of [Dedicated Nodes](/docs/dedicated-node)

You can't attach [Trader Nodes](/docs/trader-node). The same node can belong to several multichain endpoints.

## Create a multichain endpoint

<Steps>
  <Step title="Open Multichain API">
    On Chainstack, click **Multichain API** in the left menu.
  </Step>
  <Step title="Name the multichain endpoint">
    Click **Create endpoint**, enter a name of up to 30 characters, and click **Create endpoint** in the dialog. The name field starts with your organization name and the current date and time, which you can keep or replace.
    <Check>Chainstack opens the new multichain endpoint's page, and the multichain auth token is under **API key**.</Check>
  </Step>
</Steps>

A new multichain endpoint has a multichain auth token and no nodes, so the multichain auth token authorizes nothing until you attach a node. The **Multichain API** page lists your multichain endpoints with their node count, a shortened multichain auth token, and the creation date.

## Attach nodes to a multichain endpoint

<Steps>
  <Step title="Open the multichain endpoint">
    On Chainstack, click **Multichain API** and click the name of the multichain endpoint.
  </Step>
  <Step title="Add the nodes">
    Under **Connected nodes**, click **Add node**. Search for a node by name or filter the list by type (**Global** or **Dedicated**), and click **Add** next to each node you want. Click **Done** when finished.
    <Check>The nodes appear under **Connected nodes** and in the **Node** selector under **Connection details**.</Check>
  </Step>
</Steps>

You can add or remove nodes at any time, and the multichain auth token stays the same.

If you can't add a node, Chainstack dims it in the list. Hover over its **Add** button to see the reason. For example, a multichain endpoint can't hold two Global Nodes for the same protocol and network.

## Call a node with the multichain auth token

The multichain auth token takes the place of the node's own auth token in the node's endpoint URLs. To get a URL, open the multichain endpoint, select a node under **Connection details**, and copy the URL you need. The URL already contains the multichain auth token.

You can attach a node that is stopped or in maintenance, but **Connection details** shows no URLs for that node until it is running again.

For a Global Node, the URL uses the `core.chainstack.com` host with the protocol and network in the subdomain. A Dedicated Node uses its own host, so copy its URL from **Connection details** instead of building it yourself. For a REST API, the multichain auth token sits before the API path, the same as a node's auth token.

To call attached Ethereum Mainnet, Solana Mainnet, and Aptos Mainnet Global Nodes with one multichain auth token, put the multichain auth token in each node's URL:

```bash cURL
export CHAINSTACK_MULTICHAIN_TOKEN="YOUR_MULTICHAIN_AUTH_TOKEN"

curl -X POST "https://ethereum-mainnet.core.chainstack.com/$CHAINSTACK_MULTICHAIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'

curl -X POST "https://solana-mainnet.core.chainstack.com/$CHAINSTACK_MULTICHAIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"getSlot","params":[],"id":1}'

curl "https://aptos-mainnet.core.chainstack.com/$CHAINSTACK_MULTICHAIN_TOKEN/v1"
```

Replace `YOUR_MULTICHAIN_AUTH_TOKEN` with the multichain auth token from the multichain endpoint's page. Each call returns the protocol's normal response: a JSON-RPC result for Ethereum and Solana, and the ledger information for Aptos.

<Check>A request to an attached node returns a normal response. A request to a node that isn't attached returns `401 Unauthorized`.</Check>

To call a gRPC endpoint, use the node's own x-token, as described in [gRPC access via x-token](/docs/authentication-methods-for-different-scenarios#grpc-access-via-x-token).

## How Chainstack handles requests with the multichain auth token

* A request with the multichain auth token gets the same handling as a request with the node's own auth token, so the node's rate limits and [access rules](/docs/access-rules) apply.
* A request with the multichain auth token to a node that isn't attached to the multichain endpoint returns `401 Unauthorized` with the message `Access token missing or invalid. Make sure you are using the correct node endpoint.` Chainstack refuses a WSS connection to such a node with `401` during the handshake.
* When you delete a node on Chainstack, Chainstack removes the node from its multichain endpoints. The multichain endpoints and their multichain auth tokens stay.
* Removing the last node from a multichain endpoint leaves the multichain endpoint and its multichain auth token in place with no nodes.

## Find the multichain auth token

Open the multichain endpoint on the **Multichain API** page. The full multichain auth token is under **API key**, and **Copy** puts it on your clipboard. The multichain auth token starts with `mt_` and is always available on the multichain endpoint's page. The **Multichain API** list shows a shortened multichain auth token, and its copy icon copies the full value.

Treat the multichain auth token as a secret. See [Best practices for securing your Chainstack endpoint](/docs/best-practices-for-securing-your-chainstack-endpoint) for guidance.

## Replace a multichain auth token

You can't rotate the multichain auth token of a multichain endpoint. To replace the multichain auth token, for example after it leaks:

<Steps>
  <Step title="Create a new multichain endpoint">
    Create a multichain endpoint and attach the same nodes to it.
  </Step>
  <Step title="Update your applications">
    Switch your environment variables or CI secrets to the new multichain auth token.
  </Step>
  <Step title="Delete the old multichain endpoint">
    Delete the old multichain endpoint, as described in [Remove a node or delete a multichain endpoint](#remove-a-node-or-delete-a-multichain-endpoint).
  </Step>
</Steps>

## Remove a node or delete a multichain endpoint

To remove a node from a multichain endpoint, open the multichain endpoint and click the trash icon next to the node under **Connected nodes**. You can also click **Remove** next to the node in the **Add nodes** dialog. Requests to that node with the multichain auth token return `401 Unauthorized`, and the other nodes keep working.

To delete a multichain endpoint, click **Delete endpoint** on its page, or hover over its row on the **Multichain API** page and click the trash icon. If the multichain endpoint has nodes, the confirmation shows how many nodes the multichain auth token stops working on. After you click **Yes, I'm sure**, the multichain auth token stops working on every attached node. You can't undo the deletion, and your nodes stay as they are.

Advanced APIs are the node capabilities that go beyond the standard RPC method set: faster transaction propagation, and execution-level data about how a transaction ran.

| Capability | What it gives you | Available on |
| --- | --- | --- |
| [Warp transactions](/docs/warp-transactions) | Distributes your transaction through a high-speed relay network on EVM chains, or straight to the leader on Solana, so validators pick it up sooner than with regular propagation | Ethereum, BNB Smart Chain, and Solana |
| [Debug and trace APIs](/docs/debug-and-trace-apis) | The `debug_*` and `trace_*` namespaces — detailed execution data for transactions, blocks, and contract calls | Most EVM chains — see the per-chain list below |
| [Reading EVM traces](/docs/reading-evm-traces-with-calltracer-and-prestatetracer) | How to read Geth's built-in `callTracer` and `prestateTracer` output: the call tree, reverts, gas, and pre-state | Any chain that exposes debug and trace |

## Which networks support debug and trace

For a chain-by-chain answer, see the **Debug and Trace** column in [Protocols and networks](/docs/protocols-networks), which is generated from the supported-node list and stays current as protocols are added.

[Debug and trace APIs](/docs/debug-and-trace-apis) then covers each supported chain individually, since the available methods differ by client — Erigon-based chains expose the Parity `trace_*` namespace, while Geth-based chains expose `debug_*` only.

## Which networks support Warp transactions

Warp transactions run on **Ethereum**, **BNB Smart Chain**, and **Solana**. Each has its own setup page: [Ethereum trader nodes](/docs/ethereum-trader-nodes), [BNB trader nodes](/docs/bnb-trader-nodes), and [Solana trader nodes](/docs/solana-trader-nodes).

Warp transactions require a paid plan, and the transactions themselves are billed separately from requests. See [Warp transactions](/docs/warp-transactions) for the details.
